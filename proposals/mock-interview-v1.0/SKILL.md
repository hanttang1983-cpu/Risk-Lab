# Mock Interview (v1.0)

경력직 모의면접 운영 스킬. career-jd-matcher의 후속 단계로 동작하며, 분석 보고서의 "면접 예상 질문 Top 5"를 기반으로 **5개 모드 중 사용자가 선택한 모드**의 모의면접을 1회 진행한다.

## 핵심 원칙

### 1. STAR 답변은 본인 경력기술서 근거 1:1 매핑 (Fact-Checker 원칙 계승)

모든 STAR 답변(Situation·Task·Action·Result)은 사용자가 제출한 원본 경력기술서·자소서의 bullet point와 **1:1로 매핑**되어야 한다. 매핑 근거가 없는 사례·수치·결과를 답변에 절대 추가하지 않는다.

career-jd-matcher의 Stage 0 FACT-CHECKER 원칙을 그대로 계승한다. 판단이 애매하면 **쓰지 않는다.** 갭은 갭으로 두고, "보완 계획" 형태로 솔직하게 다룬다. 자세한 매핑 룰과 절대 금지 사항은 `references/star-bank.md` 참조.

### 2. 5개 모드는 사용자가 선택한다

스킬이 모드를 자동 결정하지 않는다. 시작 시 5개 모드를 1줄씩 소개하고, 사용자가 **1개 모드를 명시적으로 선택**할 때까지 대기한다. 다중 모드 동시 진행은 토큰 비용이 크므로 1회 호출당 1개 모드를 원칙으로 한다 (사용자가 명시적으로 복수 모드를 요청하면 가능).

### 3. 점수보다 약점 식별이 목적이다

0-100점 점수는 절대 평가가 아니라 **약점 식별의 도구**다. 90점이라도 약점 1개는 항상 출력한다. 80점 이하면 약점 2~3개를 우선순위로 정렬한다. 최종 출력의 핵심은 점수가 아니라 **"실제 면접에서 떨어질 수 있는 지점 N개"**다.

## 입력 점검

스킬 시작 시 다음을 확인. 빠진 것은 사용자에게 요청한다.

1. **채용공고** (URL 또는 본문) — 필수
2. **사용자 이력서/경력기술서** — 필수 (STAR 매핑 근거)
3. **지원분석보고서 docx** (career-jd-matcher 산출물) — 선택, 있으면 "면접 예상 질문 Top 5"와 회사 분석 결과를 그대로 활용해 토큰 절감
4. **자기소개서** — 선택, 있으면 답변 톤 일관성 확보에 활용
5. **모드 선택** — 5개 중 1개 (인성·PT·기술/직무·토론·AI면접)

채용공고가 URL이면 `web_fetch`로 본문 fetch. 지원분석보고서 docx가 있으면 본문을 읽어 회사 컨텍스트·면접 질문 Top 5를 추출. 부재 시 회사 분석은 간단히 재수행(웹검색 3회 이내, 정식 BCG 분석은 생략).

`references/user-profile.md`(career-jd-matcher 공유)가 있으면 로딩해 민감 토픽(짧은 재직기간, 산업 전환 등)을 사전 인지한다. 자세한 룰은 `references/question-generation.md` "Sensitive 토픽" 섹션 참조.

## 5개 모드

### 인성면접 (Behavioral)

자기소개·지원동기·강점·약점·5년 후 모습·갈등 해결·실패 경험·팀워크 등 보편 질문군. **모든 답변은 STAR 구조**로 구성. 추상적 형용사("성실합니다", "책임감이 강합니다")는 금지하고 반드시 사례 1개로 입증한다. 자기소개는 60초, 사례 답변은 90초 분량을 기본으로 한다. 자세한 질문 템플릿과 답변 룰은 `references/interview-modes.md` 인성면접 섹션 참조.

### PT면접 (Presentation)

**회사가 풀어야 할 문제 1개** + **본인의 해법 5분 발표안**. 구조 강제: 문제정의 → 진단 → 해법 → 기대효과 → 리스크. 회사 분석 보고서 Section 1.9(종합 진단)에서 회사 이슈를 1개 선정하거나, 직무 JD의 핵심 책임에서 도출. 발표안은 슬라이드 5장 분량의 텍스트 개요(슬라이드 헤드라인 + 핵심 메시지 3줄)로 작성. 자세한 구조와 분량 룰은 `references/interview-modes.md` PT면접 섹션 참조.

### 기술/직무 면접

JD의 must-have 역량별로 **사례 검증 질문**을 생성한다. 핵심 룰: **본인이 한 일과 팀이 한 일을 구분 강제**. "우리 팀이 했다"는 답변은 즉시 후속 질문 ("그중 본인이 직접 수행한 것은?")으로 압박해 직무 깊이를 검증. 정량 수치는 출처와 산출 방식을 함께 묻는다. 자세한 사례 검증 패턴은 `references/interview-modes.md` 기술면접 섹션 참조.

### 토론면접

산업·직무 주요 이슈 1개를 선정해 **찬반 양쪽 논변**을 사용자가 모두 준비한다. 평가 포인트는 **결론이 아니라 사고 과정**: 데이터 인용, 반대 입장 인정, 결론 도출의 논리적 일관성. 결론을 바꿔도 점수가 깎이지 않으나, 사고 흐름이 끊기면 감점. 자세한 토론 토픽 풀과 평가 룰은 `references/interview-modes.md` 토론면접 섹션 참조.

### AI면접 (역량검사)

인적성·게임 검사·심리 검사를 모방하지 않는다 (재현 불가). 대신 **AI면접 환경에서 자주 묻는 질문군 + 효과적 답변 톤·매너 가이드**를 제공한다. 카메라 응시, 발화 속도, 마이크로 표정, 키워드 반복 회피 등 비언어 요소를 함께 다룬다. 자세한 가이드는 `references/interview-modes.md` AI면접 섹션 참조.

## 워크플로우 (4단계)

### Step 1: 모드 선택

5개 모드를 1줄씩 소개하고 사용자가 1개를 선택할 때까지 대기. 사용자가 모드를 지정하지 않고 "알아서 해줘"라고 요청하면 **인성면접을 기본값**으로 제안하고 확인 후 진행.

### Step 2: 질문 생성

선택된 모드에 맞춰 5-10개의 질문을 생성. 질문 생성 룰은 `references/question-generation.md` 참조. 핵심 룰 요약:
- 분석 보고서가 있으면 "면접 예상 질문 Top 5"를 우선 사용, 부족분만 추가 생성
- JD의 must-have 항목 → 사례 검증형 질문
- 이력서 정량 수치 → 검증형 후속 질문 ("80건 중 가장 어려웠던 1건은?")
- 갭 항목 → 갭 검증형 질문 ("이 영역 무경험인데 어떻게 보완할 계획인가?")
- Sensitive 토픽은 `user-profile.md`의 sensitive_topics 참조

### Step 3: 답변 작성

두 가지 모드 중 사용자가 선택:
- **사용자 작성**: 사용자가 본인 답변을 입력 → 스킬은 평가만 수행
- **스킬 초안 작성**: 스킬이 이력서 기반 STAR 답변 초안 작성 → 사용자가 검토·수정

스킬이 초안을 작성할 때는 반드시 `references/star-bank.md`의 매핑 룰을 따른다. 이력서 bullet의 어느 항목을 어떤 STAR 요소로 매핑했는지 답변마다 한 줄로 명시.

### Step 4: 평가 (5-Color Harness 축약)

career-jd-matcher의 9 페르소나 중 **4명만 사용**한다. 면접 답변 평가에 적합한 시각만 추렸다:

- 🔴 **RED — 이성**: 논리·근거·정량성. STAR의 R(Result)이 정량적이고 명확한가?
- ⚪ **SILVER — 분야 전문가**: 직무 깊이. 본인이 한 일과 팀이 한 일이 구분되는가?
- 🔵 **BLUE — 공감**: 톤·진정성. 면접관에게 인간적 신뢰를 주는가?
- 🟡 **GOLD — 독자**: 최종 채용 결정자의 본능. "이 사람 뽑고 싶다"는 한 줄 인상이 남는가?

**BLACK은 제외** — 형식·구조 평가는 면접 답변 분량(60-90초)에서는 변별력이 낮음.

각 페르소나가 10점 만점으로 채점 → 합계 40점 만점 → 100점 환산(×2.5). 8.5점 미만 페르소나가 있으면 약점 1건으로 식별. 자세한 평가 룰과 가중치는 `references/interview-modes.md` 모드별 평가 가중치 섹션 참조.

## 최종 산출물

**1) 채팅 내 마크다운 보고서** — 다음 구조:

```markdown
# 모의면접 [회사명] [직무명] — [모드명] (v1.0)

## 1. 면접 정보
- 모드 / 회사 / 직무 / 진행 일자 / 입력 자료 체크

## 2. 질문 & 답변
- Q1 / 답변 (STAR 표시) / 매핑 근거 (이력서 어느 bullet)
- Q2 ...
- (5~10개)

## 3. 페르소나 평가 (4명)
| 페르소나 | 점수 (0-10) | 한 줄 코멘트 |
| 🔴 RED | X.X | ... |
| ⚪ SILVER | X.X | ... |
| 🔵 BLUE | X.X | ... |
| 🟡 GOLD | X.X | ... |
| **종합** | **XX / 100** | - |

## 4. 약점 식별표 (핵심 산출물)
| 우선순위 | 약점 | 발견 페르소나 | 개선 방향 |
| 1 | ... | SILVER | ... |
| 2 | ... | RED | ... |

## 5. 다음 단계
- 다른 모드 추천 / 재연습 권고 / 실전 면접 체크리스트
```

**2) .docx 파일 1개** — `/mnt/user-data/outputs/`에 저장:

- `모의면접_[회사명]_[직무명]_[모드명].docx`

채팅 마크다운 Section 1~5를 그대로 docx로 옮긴다. docx 생성 방법은 `/mnt/skills/public/docx/SKILL.md`를 먼저 `view`한 뒤 따른다. 작성 끝나면 `present_files`로 제시.

## 진행 시 사용자에게 알리기

시작 전 한 줄 안내:

> "모의면접 진행: 모드 선택 → 질문 생성 → 답변 작성(본인/스킬 초안) → 4 페르소나 평가 → docx 1개 생성 순서로 진행하겠습니다. 우선 5개 모드 중 1개를 선택해 주세요."

각 단계 한 줄 진행 상황 알림:
> "Step 1: 모드 선택 대기 중."
> "Step 2: [모드명] 질문 생성 중..."
> "Step 3: 답변 작성 방식 선택 대기 중 (본인 작성 / 스킬 초안)."
> "Step 4: 4 페르소나 평가 진행 중..."
> "약점 식별표 작성 중..."
> "docx 생성 중... 완료."

장황한 중간 설명은 피한다.

## 트리거되지 않아야 하는 경우

- career-jd-matcher의 정상 워크플로우 진행 중 (Step 1~5)에는 자동 트리거되지 않음. 반드시 분석 보고서 산출 **이후** 사용자의 명시적 두 번째 호출이 있어야 함.
- 면접 질문 목록만 따로 요청 ("면접 예상 질문 10개 뽑아줘") — career-jd-matcher의 Section 6.3로 충분
- 일반론적 면접 팁 질문 ("면접 잘 보는 법 알려줘")
- 면접 톤·매너 코칭 단독 요청 (이력서·JD 없음)
- 연봉 협상 면접·처우 협의 면접 (별도 워크플로우)
- 회사 분석·이력서 정교화 요청 (career-jd-matcher가 담당)

이런 경우엔 일반 응답 또는 career-jd-matcher로 안내한다.
